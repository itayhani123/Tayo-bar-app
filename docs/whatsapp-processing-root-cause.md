# Root cause מאומת — PROCESSING_FAILED

## ההוכחה

המשתמש אישר ש־Vercel Production פרס את commit
`8f6eb745dc2cf2d9f441cbfbf83c2d15084f0234`.
הוא זהה ל־HEAD המקומי; התיקונים שב־working tree אינם כלולים בו.

ב־commit הזה, `src/lib/whatsapp/attendance-worker.ts`:

- שורה 26 קוראת ל־`previewAttendance(..., false, ...)`, ללא מדיניות הערוץ.
  ה־preview אינו כולל `confirmationPolicy` וגם חוסם שיבוץ חסר.
- שורה 27 שולחת אותו ל־`complete_whatsapp_attendance_analysis`.
- שורה 28 מחליפה כל שגיאת RPC ב־`INBOX_SAVE_FAILED`, ללא הקוד המקורי.
- שורות 34–41 תופסות אותה, שומרות `PROCESSING_FAILED` ומדפיסות רק attempt.

הפונקציה במסד כבר דורשת `buttons_attendance_v2`; זו הבדיקה שבשורה 7
במיגרציה 026. כך בקשה של הקוד הפרוס נכשלת ב־PostgreSQL `22023` עם
`WHATSAPP_WORKER_VERSION_MISMATCH`, לפני יצירת סיכום לאישור או הודעה יוצאת.
זהו פער **קוד פרוס ישן מול סכמת שרת מעודכנת**, ולא בעיה ב־Cron.

בוצע שחזור אבחוני בטוח מול המסד המוגדר, על הדיווח
`a7dd28e4-e53e-4462-ae66-a9b20e0fa55f`:

| שלב | תוצאה |
|---|---|
| פענוח אמיתי ב־OpenAI | הצלחה, שתי שורות כניסה/יציאה |
| catalog ו־snapshot | הצלחה, ללא שגיאת הרשאות/עמודות |
| preview | אירוע יחיד, עובד יחיד, אפס issues |
| registration/binding/שמירה | לא הופעלו; נעצר לפני כתיבה |
| probe סינתטי ללא policy | `22023`, `WHATSAPP_WORKER_VERSION_MISMATCH` |
| probe סינתטי עם v1 | אותו כשל |
| probe סינתטי עם v2 | עובר את ה־guard; `25006` בגלל GET read-only |

`25006` בבדיקה האחרונה צפוי: הבדיקה עוצרת כשמגיעים ל־SELECT FOR UPDATE
בטרנזקציה לקריאה בלבד. השתמשה רק ב־UUIDs אפסיים ובגרסאות מדיניות, ללא
העברת snapshot או נתוני נוכחות בכתובת URL. לא נבדק mutating RPC עם נתונים
אמיתיים, ולא נכתבו רשומות או נשלחו הודעות WhatsApp. קריאת OpenAI האבחונית
כן בוצעה, ללא הדפסת הטקסט או התוצאה הגולמית.

שגיאות בשמות או בשעות הן issues/בקשות תיקון ואינן גורמות ל־guard הזה.
HTTP 200 של endpoint ה־cron אינו אישור שהדיווח עובד: ה־worker תפס את הכשל
והחזיר אותו לתור, בעוד בקשת ה־cron עצמה הסתיימה בהצלחה.

## התיקון

ה־worker המעודכן משתמש ב־`previewWhatsAppAttendance`, המסמן את המדיניות
v2 ומתיר הכנת שיבוץ לעובד קיים שזוהה בוודאות. אין הסרת guard במסד כדי
להתאים לקוד ישן, ואין שינוי בהרשאות כלליות. האישור המפורש, הכפתורים,
הטרנזקציה ומניעת הכפילויות נשארים במנגנון הקיים.

נוסף סיווג שגיאות לפני אובדן המידע המקורי. הלוג שומר stage, originalCode,
safeMessage, operation, reportId, attempt, terminal ו־policy בלבד. הוא אינו
מדפיס raw errors, bodies, טלפונים או סודות. הכשל המקורי נרשם **לפני**
ניסיון לשמור את מצב הכשל או לשלוח הודעת כשל, כך שגם כשל משני אינו מעלים אותו.

אי־תאימות גרסה, סכמה חסרה, RLS/permission וקריאת API שנדחית באופן קבוע
נעצרים ב־failed מיד. timeout, מגבלת קצב וכשל זמני מקבלים ניסיונות מוגבלים,
עד חמישה, עם backoff. נשמר fencing של lease; worker שאיבד את הבעלות אינו
משנה דיווח או יוצר הודעת כשל. מסך הדיווחים מציג הסבר בטוח ומספר ניסיונות.

`17:3` נדחה לפני יצירת לקוח OpenAI, גם כשחסרה הגדרת API. הוא מייצר בקשת
תיקון בתור הקיים ואינו הופך לכשל תשתית כללי. נוספו בדיקות לכשל 22023,
לסכמה/RLS, לסודות שאינם מופיעים בלוג, ולניסיונות חוזרים מול 429/400/401.

## הפעלה מחדש בטוחה

1. **אין צורך במיגרציה נוספת עבור תיקון זה** אם 026 כבר הוחלה כפי שאושר
   ב־probe. אין להריץ מיגרציות קודמות מחדש ואין לשנות את ה־Cron.
2. ליצור ולסקור commit חדש שכולל את תיקוני ה־working tree, כולל מדיניות
   v2, wrapper הנוכחות ושירותי 026. לפרוס אותו רק אחרי אישור.
   **Redeploy של 8f6eb74 ייכשל שוב**, כי הוא אינו מכיל את התיקונים.
3. במסך הדיווחים, לבדוק ב־Network את תשובת `/api/whatsapp/attendance`:
   `X-Tayo-WhatsApp-Policy: buttons_attendance_v2`. כאשר Vercel מספק
   `VERCEL_GIT_COMMIT_SHA`, הכותרת `X-Tayo-WhatsApp-Commit` צריכה להתאים
   ל־Source החדש. משתנה זה אינו מפתח סודי ואינו נדרש להגדרה ידנית.
4. דיווחי pending ייאספו אוטומטית ב־cron הקיים כאשר available_at מגיע.
   אין לשנות את מזהה WhatsApp או לאפס את מספר הניסיונות באופן גורף.
5. לדיווח failed, לאחר תיקון הגרסה, להשתמש בכפתור **ניסיון פענוח נוסף**
   עבור אותו דיווח בלבד. הפעולה משתמשת ב־review RPC הקיים, נשמרת ב־audit,
   ואינה יוצרת נוכחות. אישור מפורש עדיין נדרש לאחר הכנת הסיכום החדש.
6. לוודא שלוגי claimed/prepared נושאים v2, שהדיווח הגיע ל־review ושהסיכום
   נשלח. ללחוץ אישור על דיווח בדיקה בלבד ולוודא שיבוץ ושעות פעם אחת.

לא בוצעו commit, פריסה, שינוי Cron, איפוס תורים או כתיבה ל־Production.
