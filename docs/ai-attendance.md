# קליטת נוכחות ב־Tayo AI

היכולת נוספת לצ'אט הקיים. רשימה עם שורות וכותרות נוכחות מזוהה אוטומטית; עבור כותרות עם שגיאות או הודעה חלקית אפשר לסמן „קליטת רשימת נוכחות”. אין החלפה של כלי השיחה והפעולות הקיימים.

## הפעלה

1. להחיל את `supabase/migrations/019_ai_attendance_import.sql` אחרי מיגרציות 002, 004, 005 ו־016. אין שינוי או מחיקה של נתוני נוכחות קיימים.
2. נדרשים משתני השרת הקיימים: `OPENAI_API_KEY`, `SUPABASE_SERVICE_ROLE_KEY`, ו־`NEXT_PUBLIC_SUPABASE_URL`; `OPENAI_MODEL` ממשיך לבחור את מודל השיחה. המודל חייב לתמוך ב־Structured Outputs.
3. בדיקת פענוח חיה, ללא גישה למסד: `node --import ./scripts/test-register.mjs scripts/check-ai-attendance.ts`.

## תהליך

- `/api/ai-assistant/attendance` מאמת משתמש דרך `auth.getUser`, בודק role עדכני ו־Origin, מגביל גוף בקשה ומפעיל את מכסת ה־AI הקיימת בפענוח.
- OpenAI Responses מחלץ JSON בסכמה קפדנית עם `zodTextFormat`, ללא כלים, מזהים, שכר או כתיבה למסד. פלט חסר או מסורב נכשל בלי שמירה. אין השלמת שנה או שעה חסרה.
- השרת מחפש אירועים קיימים לפי יום וחודש בכל השנים; אולם ויום בשבוע מצמצמים התאמות. כמה תוצאות מחייבות בחירה. אם האולם/היום אינם תואמים, מוצגים מועמדים מאותו תאריך לבחירה מפורשת בלבד. אם אין מועמדים, יש לערוך את הודעת המקור או להסדיר אירוע במסך האירועים; אין יצירת אירוע אוטומטית.
- עובדים מותאמים לפי שם מלא או שם פרטי יחיד; שיבוץ קיים יכול לצמצם שם פרטי למועמד יחיד. במבנה הקיים **אין שדה כינויים**, ולכן אין הנחה שכינויים קיימים. שמות לא מוכרים ושגיאות כתיב מחייבים בחירה בעובד קיים מהטבלה; לא נוצרים עובדים. אם שם פרטי נשאר עמום לצד שם מלא, בחירה מפורשת באותו עובד מאחדת שורות כניסה ויציאה משלימות. שעות סותרות חוסמות שמירה ומחייבות תיקון הודעת המקור.
- אפשר לערוך עובד, שעות והערות. כל שינוי מבטל את האישור הפעיל ומחייב „בדוק את התיקונים והכן אישור”. כפילות מקור מחייבת תיקון הודעת המקור. שעות חסרות מוצגות וחוסמות שמירה עד להשלמה; הן אינן דורסות שעות קיימות ב־null.
- השעות מפורשות ב־Asia/Jerusalem בעזרת ממיר הזמנים הקיים. יציאה מוקדמת מהכניסה לפני 12:00 ביום הבא היא חציית חצות; משמרת ללא משך חיובי, מעל 16 שעות, או זמן עמום/חסר במעבר שעון מחייבים תיקון. חישוב משך משתמש במחשבון הנוכחות הקיים.
- הטבלה מציגה את השעות הקודמות והאם הפעולה תעדכן שיבוץ או תיצור שיבוץ חדש. שיבוצים חדשים דורשים checkbox אישור נפרד להכנת ההצעה. הערות פתיחה/סגירה/אחמ״ש נשמרות כהערות, ולא משנות תפקיד או תנאי שכר.
- הכנת ההצעה שומרת רק טיוטה פרטית עם snapshot ותוקף של עשר דקות. רק כפתור „אשר ושמור את כל השעות” שולח בקשת confirm נפרדת. אין נתיב אישור מתוך כלי המודל או טקסט „כן”.
- RPC פרטי מבצע transaction לכל הרשימה: role חי, נעילות, snapshot, ולידציה חוזרת, חיפוש שיבוץ קיים, עדכון שעות בלבד או יצירת שיבוץ שעתי בשכר ברירת המחדל של העובד (כמו תהליך השיבוץ המורשה הקיים). שכר גלובלי/שעתי ותפקיד של שיבוץ קיים נשמרים. התנגשות עם נוכחות באירוע אחר או שיבוץ כפול חוסמת שמירה. כשל בשורה כלשהי מחזיר את כל השינויים לאחור.
- השכר אינו נתון materialized: חישובי שכר ועלות כוח אדם הקיימים קוראים `event_assignments`. ההצלחה מרעננת React Query לאירועים, שיבוצים, לוח שנה, דשבורד ושכר, ומציעה קישור לאירוע.
- לחיצה כפולה חוזרת לאותה תוצאת transaction; הדבקה חוזרת משתמשת בטביעת תוכן ושיבוצים קיימים למניעת כפילות. אם שעות שונו ידנית לאחר השמירה, הדבקה חוזרת מכינה אישור חדש במקום להציג הצלחה היסטורית.
- `ai_attendance_audit` מתעד לכל שורה שעות והערות לפני ואחרי, משתמש, שיבוץ וטיוטה. `ai_action_audit` הקיים מקבל גם רישום כולל. רק owner רשאי לקרוא את audit; תצוגת manager אינה מכילה שכר.

טיוטות הנוכחות נשמרות במסד לצורך אישור/מניעת כפילות; כרטיסי הנוכחות עצמם נשמרים רק בזמן שהצ'אט פתוח. ברענון אפשר להדביק שוב את הרשימה. הודעות WhatsApp עסקיות אינן נשלחות ממסלול הקליטה המרוכזת.

## בדיקות

`npm run typecheck`, `npm run lint`, `npm test`, `npm run build`.

בדיקות הנוכחות כוללות את ההודעה המלאה, זהויות עמומות, הערות, שעות חסרות וכפולות, חצות, DST, איתור אירוע בלי שנה, חוזה Structured Outputs, הרשאות API, ושמירות אמיתיות ב־PostgreSQL מקומי דרך PGlite עם מיגרציה 019. אין בבדיקות האוטומטיות כתיבה ל־Supabase המרוחק.

אחרי החלת המיגרציה יש לבצע בדיקת דפדפן כ־owner וכ־manager מול סביבת בדיקה: בחירת אירוע, תיקוני שורות, אישור שיבוצים, שמירה, פתיחת האירוע ואימות מסך השכר. לבדוק גם שתי לשוניות וניסיון אישור אחרי שינוי ידני.

מימוש Structured Outputs לפי [התיעוד הרשמי של OpenAI](https://developers.openai.com/api/docs/guides/structured-outputs).
